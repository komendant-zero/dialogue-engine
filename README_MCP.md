# Dialogue Engine — Поддержка MCP (Model Context Protocol)

Модуль **`mcp_server.py`** превращает Dialogue Engine в MCP-сервер, позволяя AI-ассистентам (Antigravity, Claude Desktop, Cursor, Continue и др.) напрямую читать, редактировать, проверять и расширять сценарии ваших визуальных новелл.

Благодаря встроенному плагину **`Live Watcher` (reload_plugin.py)**, любые изменения, сделанные искусственным интеллектом через MCP, **мгновенно отображаются на холсте редактора без перезапуска**!

---

## 🚀 Быстрый запуск

### 1. Подключение в Antigravity / Claude Desktop / Cursor

Добавьте конфигурацию в ваш файл настроек MCP (например, `~/.gemini/config/mcp_config.json` в Antigravity или `claude_desktop_config.json` в Claude Desktop):

```json
{
  "mcpServers": {
    "dialogue-engine": {
      "command": "python",
      "args": ["d:/DE/mcp_server.py", "D:/projects/Violant/game/violant.json"],
      "env": {
        "PYTHONIOENCODING": "utf-8"
      }
    }
  }
}
```

*Если путь к проекту не передан в аргументах, сервер автоматически ищет `violant.json`.*

## 🛠 Доступные инструменты (Tools) для ИИ:

1. **`de_get_stats`** — общая статистика сценария (число узлов, персонажи, число реплик каждого героя, старты, листья).
2. **`de_find_leaf_endpoints`** — список всех конечных точек графа, где сейчас обрывается сюжет (идеально для продолжения сценария).
3. **`de_get_node`** — полная информация по узлу (текст, автор, тип, входящие и исходящие связи).
4. **`de_search_nodes`** — поиск реплик по персонажу, фрагменту текста или типу узла.
5. **`de_trace_branch`** — печать диалоговой ветки от заданного узла в виде понятного сценария с развилками.
6. **`de_add_story_node`** — создание новой реплики или описания сцены (`character`, `content`, опционально `connect_from_id`). Автоматически рассчитывает координаты `x`, `y` справа от родителя.
7. **`de_add_choice_node`** — создание интерактивной развилки с несколькими вариантами выбора для игрока.
8. **`de_add_condition_node`** — создание логического узла условия (например, `violant_river == 1`) с выходами `0` (True) и `1` (False/Else).
9. **`de_connect_nodes`** — соединение двух узлов.
10. **`de_disconnect_nodes`** — разъединение узлов.
11. **`de_update_node`** — редактирование текста или спикера у существующего узла.
12. **`de_delete_node`** — удаление узла и очистка всех связей.
13. **`de_validate_graph`** — проверка целостности графа (поиск битых ссылок, изолированных узлов, ошибок условий).
14. **`de_export_renpy`** — компиляция и экспорт графа напрямую в `script.rpy`.
15. **`de_load_project`** / **`de_save_project`** — открытие и сохранение файлов `.json`.
